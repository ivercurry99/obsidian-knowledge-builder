# 知识库设计思路

> 本文件解释知识库的底层设计，供需要向用户说明「为什么这样搭」或调整结构时读取。日常执行不必每次加载。

## 核心：流转，不是存储

知识库的价值不在「存了多少」，而在「东西能不能流起来、被复用」：

```text
新东西 → 00-Inbox（暂存）→ 确认走向 → 10-Areas / 20-Projects / 30-Output
```

**Inbox 是流水线，不是仓库。** 每条进来的东西都必须有一个终点——要么升格，要么删除，不允许「什么都不做，一直躺着」。这是整套结构的硬约束：Inbox 一旦开始囤积，知识库就退化成收藏夹。

## Inbox 三个桶，三个终点

`00-Inbox/` 下三个桶处理方式不同，但出口逻辑一致：处理过的条目都打 `√` 或标 `status`，一眼就能看出哪些还没处理。

| 桶 | 是什么 | 处理方式 | 终点 |
|------|------|----------|------|
| `待沉淀/` | 学过但没吃透的资料 | 沉淀成结构化笔记 | `10-Areas/` 笔记 + 可选学习 + `√` |
| `灵感/` | 自己的想法碎片 | 判断身份（不需要读） | 并入已有笔记 / 待沉淀 / Projects / Output / 删除 + `√` |
| `资源/` | 收藏的文章、链接、视频 | 读完后的价值判断 | 转 `待沉淀/` 或删除 + `√` |

### 灵感为什么要五面分流

灵感是脑子里冒出来的碎片，**它不是「资料」，不需要读懂，需要的是判断它该变成什么**。如果只给它一条路（比如只能进 Areas），就会出现两种失败：

- 明明是个"要去做的事"，被当成知识存起来，永远不执行；
- 明明是个内容选题，被塞进 Areas，写的时候又找不到。

所以给五个出口，每条都有明确判断标准：

| 去向 | 判断标准 | 落到哪 |
|------|----------|--------|
| 并入已有笔记 | 该领域已有相关笔记，这条是补充 | 追加到原笔记，不新建 |
| 转待沉淀 | 想明白了、值得做成正式知识，但还没写透 | `00-Inbox/待沉淀/{领域}/` |
| 成项目 | 能变成一件具体要做的事 | `20-Projects/ing/` |
| 成输出 | 能变成对外视频 / 文章 | 调用 `40-Skills/知识视频创作专家`，产物进 `30-Output/ing/` |
| 删除 | 想清楚了不值得留 | 直接删除 |

**不设「成知识」出口**：想变成 Areas 笔记的，一律先进 `待沉淀/`，由沉淀路线统一处理。沉淀只留一套写法和一套质量标准，不在灵感路线里再造一份。

**「并入已有笔记」必须保留**：否则同一主题会散成十几篇碎笔记，找的时候反而找不到。

**成输出要调用专家，不是只建一张空笔记**：知识库里的 `40-Skills/` 存的就是专家，选题落在 `30-Output/` 之前应该由专家把它撑成真正的脚本。专家文件缺失或题材不匹配时才降级为普通选题笔记。

### 删除就是删除，不给第二个黑洞

不设 `灵感/_归档/`。归档只是把东西从一个黑名单搬进另一个黑名单，终点依然是「没处理」。如果用户舍不得删，那说明这条有去向——去升格，不给中间地带。

### 暂缓不设期限，但每次都要重新露面

「再想想」是最容易伪装成处理动作的拖延。既然是暂缓，就不写截止日期；但**每次扫描都必须把 `status: pending-review` 的条目重新列出来问一次**，让它持续回到用户面前。不设期限靠的不是遗忘，而是反复提醒。

## 每一层的作用

| 目录 | 作用 | 例子 |
|------|------|------|
| 00-Inbox | 所有新东西第一站，先丢进来，不分类 | 刚收藏的文章、突然的想法 |
| 10-Areas | 已消化、已掌握的知识，按领域分 | 吃透的方法论、整理好的笔记 |
| 20-Projects | 正在做或想做的事，按状态分 | 一个课程、一个副业项目 |
| 30-Output | 已对外发布的成果 | 发出去的文章、视频 |
| 40-Skills | AI 协作工具与提示词 | 链接修复脚本 |
| 90-大脑说明 | 最高优先级入口：档案 + 操作护栏 | 个人档案、操作约束 |

## 大脑说明是「最高优先级入口」

`90-{昵称}的大脑说明/` 不是普通文件夹，它是整个知识库的「使用说明书」。AI 协作前必须先读它。它回答三个问题：

1. **你是谁** → 个人档案
2. **你想要什么** → 职业框架、人生理想
3. **AI 怎么帮你** → 操作约束（Harness）

因此它包含 6 个文件，而不是只有一份档案：

| 文件 | 回答的问题 |
|------|-----------|
| README.md | 整个文件夹的入口 + 知识库地图 |
| 个人档案.md | 你是谁、你的性格、职业框架、人生理想 |
| agents.md | AI 的操作护栏（完成标准、文件约束、建议 vs 执行） |
| 初始化提示词.md | 换新会话时快速恢复上下文 |
| 文件追踪.md | 文件移动/重命名后的链接更新机制 |
| 备份方案.md | 定期备份知识库 |

## 领域与子领域

- 领域文件夹用**纯名称**（如 `数据分析`），不带数字前缀。
- 子领域才用数字前缀（如 `1-业务理解`），只在领域下有多个子块时才建。
- `00-Inbox/待沉淀/` 镜像领域文件夹，与 `10-Areas/` 一一对应，升格时不用改路径。

## 知识沉淀流程

```text
读完整理解 → 判断归属 → 问确认 → 写成结构化笔记 → 放入对应 Area → 原文加 √ + 指向产出
```

### 待沉淀 → Areas 升格三标准

1. 能用自己的话讲清楚
2. 在工作中或生活中用过
3. 能教给别人

## 待沉淀路线：沉淀与学习

`00-Inbox/待沉淀/` 存**资料**，`10-Areas/` 存**沉淀后的笔记**。用户说「同步学习沉淀的知识」，启动流程：

```text
扫描资料 → 沉淀成 Areas 笔记 → 逐个询问「要不要学习」→ 学习（learn-anything-fast）→ 笔记旁打勾 √
```

- **沉淀**：把资料消化成结构化笔记，升格到 `10-Areas/{领域}/`（读 → 判断归属 → 写笔记 → 放入 Area）。
- **询问**：每沉淀完一篇，问「要不要学习这篇？」。不要则跳过，不打勾。
- **学习**：要则用 `learn-anything-fast` 深度学习（默认 Compress 模式）。
- **打勾**：学习完，在 Areas 笔记文件名末尾加 √（或 `status: learned`），标记「已学习」。

详细格式见 [references/learning-sync.md](references/learning-sync.md)。

### 两种沉淀模式

| 用户说 | 怎么做 |
|--------|--------|
| 「小白式沉淀」 | 大白话、生活类比、场景引入、假设零基础 |
| 「知识沉淀」/ 没说 | 保留原文信息密度，不精简过头，关键细节不能丢 |

## 文件命名规则

- 同一主题 ≥ 2 个文件才建子文件夹，单个放 Area 根目录。
- 有逻辑顺序标数字（`1-`、`2-`），无逻辑顺序用字母（`A-`、`B-`）。
- 文件夹名匹配待沉淀目录名。

## frontmatter 约定

每个文件都带 YAML frontmatter，让 AI 能一眼判断文件类型：

```yaml
---
tags: [标签]
created: YYYY-MM-DD
type: root | index | profile | constraint | skill | skill-hub
---
```

- `type` 是给 AI 看的「文件身份」：`profile` 是档案、`constraint` 是护栏、`root`/`index` 是入口。
- 个人档案额外标 `priority: P0`，表示最高优先级。

## 为什么是这套结构

- **Inbox 兜底**：降低「先分类」的心智负担，随手丢，有空再消化。
- **三个桶都有终点**：资源转待沉淀或删、灵感五面分流、待沉淀升格 Areas，没有任何一类能无标记地囤积。
- **待沉淀镜像领域**：Inbox 里的待沉淀按领域分，升格到 Areas 时路径一一对应，不用临时想放哪。
- **Areas 与 Projects 分离**：已掌握的知识和正在做的事分开，避免「知识」被「任务」淹没。
- **Output 独立**：输出是知识的内化，单独一层鼓励对外表达。
- **大脑说明前置**：让换新会话 / 新 Agent 后能快速接上，并约束 AI 的操作边界。
